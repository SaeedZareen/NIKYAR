# نیک‌یار

سامانه‌ی یکپارچه‌ی مدیریت فرایند (BPMS) و منابع سازمانی، ماژولار و کاملاً فارسی، برای نصب روی سرور خود سازمان (۱۰ تا ۵۰۰ کاربر). همه‌چیز راست‌به‌چپ، با تاریخ شمسی و ارقام فارسی است و روی رایانه، لپ‌تاپ و موبایل کار می‌کند.

- **نسخه‌ی منتشرشده:** ۰٫۶ (ماژول «پرونده‌ی پرسنلی»: پرونده و سوابق کارکنان، ۳۳ فرایند آماده‌ی پرسنلی با یک کلیک، ورود و خروج با اکسل، گزارش نیروی انسانی؛ همراه گردش کار ۰٫۵ و فرم‌ساز ۰٫۴). تغییرات هر نسخه: [docs/CHANGELOG.md](docs/CHANGELOG.md)
- **کار بعدی:** ۱٫۰ — آماده‌سازی فروش (فاز ۶): راه‌اندازی نخستین، PostgreSQL، نصب‌کننده و سرویس ویندوز، به‌روزرسانی امن، امنیت، آزمون بار و راهنما.
- **نقشه‌ی راه کامل:** [docs/ROADMAP.md](docs/ROADMAP.md)
- **راهنمای نصب کامل** (ویندوز و لینوکس، سرویس، PostgreSQL، انتقال به سرور دیگر، عیب‌یابی): [docs/INSTALL.md](docs/INSTALL.md)

## نصب روی ویندوز

خلاصه‌ی نصب در ادامه است؛ راهنمای کامل با سرور لینوکس، PostgreSQL، انتقال به سرور دیگر و عیب‌یابی: **[docs/INSTALL.md](docs/INSTALL.md)**.

### پیش‌نیازها (یک‌بار)

- [Python 3.13](https://www.python.org/downloads/) — نسخه‌های ۳٫۱۲ تا ۳٫۱۴ پذیرفته است؛ اگر نسخه‌ی دیگری (مثلاً ۳٫۱۵) هم نصب است اشکالی ندارد، `install.bat` نسخه‌ی مناسب را خودش انتخاب می‌کند.
- [Node.js 22 LTS یا جدیدتر](https://nodejs.org/)
- [Git](https://git-scm.com/download/win)

### نصب

در پوشه‌ی پروژه:

1. `install.bat` را اجرا کنید: بسته‌ها نصب، رابط کاربری ساخته و پایگاه داده آماده می‌شود (چند دقیقه، با اینترنت). در نصب تازه می‌پرسد کدام پایگاه داده: `1` درونی (پیشنهادی) یا `2` سرور PostgreSQL ([پایگاه داده‌ی PostgreSQL](#پایگاه-دادهی-postgresql-سازمانهای-بزرگتر)).
2. `start.bat` را اجرا کنید. نشانی سامانه و، بار اول، **کد راه‌اندازی** (مثل `RWNS-M5AB`، زیر «First-run setup») در پنجره نمایش داده می‌شود.
3. در مرورگر `http://localhost:8000` را باز کنید؛ جادوگر **«راه‌اندازی نخستین»** باز می‌شود. کد راه‌اندازی را وارد کنید و یکی را برگزینید:
   - **راه‌اندازی سازمان** (برای کار واقعی): نام و لوگوی سازمان و ماه آغاز سال مالی، حساب راهبر سامانه (نام، نام کاربری، گذرواژه)، روزها و ساعت کاری، و در صورت داشتن، فایل لایسنس (بدون آن ۳۰ روز آزمایشی). پس از «پایان راه‌اندازی» با همان حساب وارد سامانه می‌شوید؛ همه‌ی این مقدارها بعداً در «تنظیمات» تغییر می‌کنند.
   - **نسخه‌ی نمایشی** (برای آشنایی): سازمان، واحدها و کاربران نمونه ساخته می‌شوند؛ با کاربران نمونه‌ی جدول زیر وارد شوید.

کد راه‌اندازی فقط در پنجره‌ی سرور دیده می‌شود تا کسی در شبکه جز راهبر نتواند سامانه را راه‌اندازی کند. پس از ساخت نخستین کاربر، این جادوگر دیگر باز نمی‌شود.

### کاربران نسخه‌ی نمایشی (گذرواژه‌ی همه: `nikyar123`)

| نام کاربری | نقش |
|---|---|
| `admin` | مدیر کل (همه‌ی بخش‌ها) |
| `it_manager` | راهبر سامانه: کاربران، نقش‌ها، سوابق، ساختار سازمانی، فهرست‌های پایه، جانشینی‌ها، تنظیمات، تقویم کاری، پشتیبان‌گیری، کارهای سامانه، لایسنس |
| `hr_manager` / `hr_expert` | منابع انسانی: ساختار سازمانی، فهرست‌های پایه، جانشینی‌ها و پرونده‌های پرسنلی |
| `ceo`، `fin_manager` | مدیران: مشاهده‌ی کاربران و ساختار |
| `accountant`، `developer` | بدون نقش (پیشخوان، کارتابل، درخواست جدید، درخواست‌های من، فرم‌ها، ثبت‌های من، اعلان‌ها و حساب من) |

طراحی فرم‌ها و فرایندها و مدیریت همه‌ی درخواست‌ها را فعلاً فقط `admin` دارد؛ برای دیگران، مجوزهای «طراحی فرم‌ها و دیدن همه‌ی ثبت‌ها»، «طراحی فرایندها» و «مدیریت همه‌ی درخواست‌ها» را در «نقش‌ها و مجوزها» به نقشی بدهید (مدیر یک فرایند را هم می‌توان در «مشخصات» همان فرایند تعیین کرد).

داده‌ی نمونه فقط در «نسخه‌ی نمایشی» و روی پایگاه داده‌ی تازه ساخته می‌شود و داده‌ی واقعی را هرگز تغییر نمی‌دهد. اگر نسخه‌ی نمایشی را برای کار واقعی نگه می‌دارید، گذرواژه‌ی `admin` را از «حساب من › گذرواژه» عوض کنید.

## اجرا، توقف و به‌روزرسانی

| کار | چه کنید |
|---|---|
| **روشن کردن** | `start.bat`؛ پنجره را تا پایان کار باز نگه دارید (کارهای پس‌زمینه مثل پشتیبان روزانه و ارسال پیامک هم در همین پنجره اجرا می‌شوند). |
| **خاموش کردن** | در پنجره‌ی `start.bat` کلید `Ctrl+C` یا بستن پنجره. |
| **درگاه دیگر** | `start.bat --port 8080` (در این صورت `allow-network.bat` برای ۸۰۰۰ کافی نیست). |
| **اجرای خودکار (سرویس ویندوز)** | `service.bat` (دسترسی Administrator می‌خواهد) و گزینه‌ی ۱: سامانه بدون پنجره، با روشن شدن ویندوز خودش بالا می‌آید و پس از خطا خودکار دوباره روشن می‌شود. برای سرور واقعی همین را بزنید. توقف، شروع، کد راه‌اندازی و حذف سرویس از همان منو؛ گزارش کار سرور در `backend\data\logs`. |
| **به‌روزرسانی** | `update.bat` (آخرین نسخه را می‌گیرد و نصب را تکرار می‌کند)، سپس `start.bat`. اگر سامانه سرویس است، `update.bat` را با «Run as administrator» اجرا کنید؛ سرویس را خودش متوقف و دوباره روشن می‌کند. داده‌ها در `backend\data` می‌مانند و پاک نمی‌شوند. |

## استفاده از رایانه‌ها و موبایل‌های دیگر (شبکه‌ی محلی)

لپ‌تاپ یا رایانه‌ی شما سرور می‌شود و هر دستگاهی که به **همان شبکه (همان مودم یا وای‌فای)** وصل است می‌تواند وارد شود:

1. `start.bat` را اجرا کنید. در پنجره خطی مثل `From other devices (LAN): http://192.168.1.20:8000` می‌بینید.
2. همان نشانی را در مرورگر رایانه یا موبایل دیگر باز کنید.
3. اگر باز نشد، دیوار آتش ویندوز مانع است: بار اول ویندوز می‌پرسد، «Allow» را بزنید؛ یا یک‌بار `allow-network.bat` را با راست‌کلیک و «Run as administrator» اجرا کنید.
4. شبکه‌ی وای‌فای ویندوز باید «Private» باشد، نه «Public» (Settings ← Network ← Wi-Fi ← Network profile type).

## راه‌اندازی برای یک سازمان

پیشنهاد ترتیب کارها پس از نصب (گروه‌های «پیکربندی»، «سازمان و کاربران» و «نگه‌داری سامانه» در منوی کناری):

1. **تنظیمات › مشخصات سازمان:** نام کامل و کوتاه، شناسه‌ی ملی، نشانی، لوگو.
2. **تنظیمات › سال مالی:** ماه آغاز سال مالی.
3. **تنظیمات › روزها و ساعت کاری:** روزهای کاری و ساعت هر روز (مثلاً پنجشنبه نیمه‌وقت).
4. **تقویم کاری:** تعطیلات رسمی سال جاری خودکار ثبت شده‌اند؛ تعطیلات خاص سازمان را با کلیک روی روز اضافه کنید.
5. **ساختار سازمانی:** واحدها، سمت‌ها و مدیر هر واحد.
6. **نقش‌ها و مجوزها،** سپس **کاربران** و انتصاب هر کاربر در سمتش.
7. **تنظیمات › پیامک و ایمیل:** درگاه پیامک و سرور ایمیل، و «ارسال آزمایشی».
8. **تنظیمات › پشتیبان‌گیری خودکار:** ساعت پشتیبان روزانه (پیش‌فرض ۰۲:۰۰) و تعداد نسخه‌ها.
9. **ماژول‌ها و لایسنس:** «شناسه‌ی نصب» را برای صادرکننده بفرستید و فایل لایسنس را بارگذاری کنید.
10. **طراحی فرم‌ها:** «فرم جدید از الگو» (درخواست خرید، درخواست کالا از انبار، صورت‌جلسه، فرم ارزیابی) نقطه‌ی شروع خوبی است.
11. **فرایندهای آماده** (منوی «گردش کار»): «فعال‌سازی همه» تا کارکنان مرخصی، مأموریت، اضافه‌کار و… را از «درخواست جدید» بفرستند. پیش از آن «تنظیمات › منابع انسانی: نقش‌ها و سقف مبلغ» را پر کنید (مرحله‌ی منابع انسانی به همان نقش می‌رسد) و هر کارمند را در «پرونده‌های پرسنلی» به حساب کاربری‌اش وصل کنید. نتیجه‌ی هر درخواست تأییدشده در زبانه‌ی «درخواست‌ها و نامه‌ها»ی پرونده می‌نشیند و مانده‌ی مرخصی را کم می‌کند؛ گواهی‌ها پس از تأیید منابع انسانی با سربرگ، شماره و امضای تأییدکننده آماده‌ی چاپ‌اند (اعلان با پیوند چاپ به درخواست‌دهنده می‌رسد).
12. **طراحی فرایندها:** «الگوی درخواست خرید»؛ در «مشخصات» هر فرایند شروع‌کنندگان، مدیران فرایند (کار بی‌گیرنده به آن‌ها می‌رسد) و الگوی شماره را تعیین کنید، گیرنده‌ی هر مرحله را بگذارید و منتشر کنید.
13. **تنظیمات › پیامک و ایمیل › نشانی سامانه:** برای پیوند صفحه‌ها در ایمیل‌ها و «تأیید با یک کلیک از ایمیل».
14. **تنظیمات › سامانه و امنیت:** مدت اعتبار ورود (پیش‌فرض ۱۰ ساعت)، سقف تلاش ورود و ثبت فرم در دقیقه، اعتبار پیوند تأیید سریع و مدت نگه‌داری سابقه‌ی کارهای سامانه. پیش‌فرض‌ها برای بیشتر سازمان‌ها مناسب‌اند.
15. **با ماژول پرونده‌ی پرسنلی، تنظیمات › منابع انسانی:** «نقش‌ها و سقف مبلغ» (چه نقشی کار منابع انسانی، امور مالی و مدیرعامل را انجام می‌دهد و از چه مبلغی تأیید مدیرعامل لازم است) و «متن نامه‌ها» (متن گواهی‌ها با دکمه‌های درج مشخصات کارمند)، «ورود کارمند» (طول دوره‌ی آزمایشی و یادآوری ارزیابی)، «دوران خدمت» (یادآوری پیش از پایان قرارداد و هشدار پیش از پایان اعتبار مدارک)، «مالی و رفاه» (سقف مساعده و وام، شمار اقساط، ضامن، سقف درمان و مبلغ کمک‌هزینه‌ها) و «مرخصی و تردد» (سهمیه‌ی سالانه، پیش‌فرض ۲۶ روز، با مقدار جدا برای هر نوع استخدام؛ سقف انتقال مانده؛ سقف اضافه‌کار؛ و جدول نوع‌های مرخصی با سقف و پیوست هر کدام). پیش‌فرض‌ها بر پایه‌ی قانون کار است.

## راهنمای بخش‌ها

### برای همه‌ی کاربران

- **پیشخوان:** خوشامد، شمار کارهای منتظر کارتابل، سمت‌های شما و دسترسی سریع به بخش‌های مجاز؛ برای بینندگان پرونده‌ها کارت «نیروی انسانی» (شاغلان، ورود و خروج ماه، مدارک رو به پایان اعتبار).
- **اعلان‌ها:** زنگوله‌ی نوار بالا آخرین اعلان‌ها را نشان می‌دهد؛ با زدن هر اعلان به صفحه‌ی مربوط می‌روید. صفحه‌ی «اعلان‌ها» همه را با جست‌وجو و فیلتر دارد.
- **حساب من** (از منوی کاربر، بالا سمت چپ):
  - **مشخصات من:** موبایل و ایمیل (پیامک و ایمیل اعلان‌ها به همین‌ها می‌رود) و تصویر امضا برای چاپ‌ها. نام و سمت را راهبر سامانه تعیین می‌کند.
  - **گذرواژه:** تغییر گذرواژه؛ ورود شما در دستگاه‌های دیگر باطل می‌شود.
  - **اعلان‌ها:** کدام اعلان‌ها علاوه بر سامانه با پیامک یا ایمیل هم برسد.
  - **جانشینی:** پیش از مرخصی یا مأموریت جانشین تعیین کنید؛ در آن بازه کارهای شما به جانشین هم می‌رسد (زبانه‌ی «جانشینی» کارتابل). با «فقط این فرایندها» می‌توانید برای فرایندهای مشخص (مثلاً تأیید خرید) جانشین جدا بگذارید؛ برای آن فرایند، همین جانشین ویژه بر جانشین کامل مقدم است.
- **فرم‌ها:** فرم‌های قابل پر کردن به تفکیک دسته؛ کنار هر فرم وضعیتش (بسته، تکمیل ظرفیت، پر کرده‌اید) یا ظرفیت باقی‌مانده.
  - هنگام پر کردن، پیش‌نویس کمی پس از هر تغییر خودکار ذخیره می‌شود (وضعیت زیر عنوان صفحه)؛ پیش‌نویس‌های نیمه‌کاره بالای همین صفحه می‌مانند تا ادامه دهید یا حذف کنید.
  - فرم مرحله‌ای: «مرحله‌ی بعد» تا فیلدهای الزامی همان مرحله پر نشده جلو نمی‌رود.
  - با دکمه‌ی ثبت، اطلاعات در پنجره‌ی **«مرور و تأیید نهایی»** نمایش داده می‌شود: «بازگشت و ویرایش» به فرم برمی‌گرداند و «تأیید و ثبت» ارسال می‌کند.
  - پس از ثبت، بنا به تنظیم فرم به «فرم‌ها» برمی‌گردید یا صفحه‌ی تأیید (با شماره‌ی پیگیری و «ویرایش ثبت» اگر فرم مهلت ویرایش دارد) را می‌بینید.
- **درخواست جدید:** فرایندهای منتشرشده‌ای که اجازه‌ی شروعشان را دارید، به تفکیک دسته، و پیش‌نویس‌های نیمه‌کاره‌ی درخواست بالای صفحه.
  - پر کردن مثل «فرم‌ها» است (پیش‌نویس خودکار، مرور و تأیید نهایی)؛ پس از ثبت، صفحه‌ی تأیید با شماره‌ی درخواست و درخواست برای مرحله‌های فرایند فرستاده می‌شود.
  - اگر نقش شما در مشخصات فرایند جزو «ثبت به نام دیگری» باشد، بخش «ثبت‌کننده» بالای فرم می‌آید: «به نام» همکار را انتخاب کنید (با ✕ به نام خودتان برمی‌گردد).
- **درخواست‌های من:** همه‌ی درخواست‌هایی که ثبت کرده‌اید یا به نامتان ثبت شده، با وضعیت و مرحله‌ی فعلی.
  - صفحه‌ی هر درخواست: کار اکنون نزد چه کسی است و مهلتش، نمودار فرایند (مرحله‌های انجام‌شده سبز و مرحله‌ی فعلی پررنگ)، اطلاعات فرم، گفت‌وگو با گیرنده‌ها و تاریخچه.
  - **لغو درخواست** تا وقتی هیچ مرحله‌ای تصمیم نگرفته است؛ **چاپ** با جدول تأییدها و امضای «حساب من» هر تأییدکننده.
- **کارتابل:** کارهایی که در فرایندها به شما رسیده است؛ شمارشان کنار «کارتابل» در منو و در پیشخوان می‌آید.
  - کار دارای مهلت، ستون «مهلت» را پر می‌کند؛ پس از گذشتن مهلت نشانه‌ی قرمز «دیرکرد» می‌گیرد.
  - **منتظر من:** کارهای خود شما. **گروهی:** کارهایی که به چند نفر (مثلاً همه‌ی کارپردازها) رسیده است؛ با «برداشتن کار»، کار فقط برای شما می‌ماند و با «رها کردن» به گروه برمی‌گردد. **جانشینی:** کارهای کسانی که امروز جانشینشان هستید. **انجام‌شده:** کارهایی که انجام داده‌اید.
  - در صفحه‌ی هر کار: خلاصه‌ی درخواست، فرم (فقط فیلدهایی که فرایندساز برای این مرحله قابل ویرایش گذاشته تغییر می‌کنند)، یادداشت، دکمه‌های تصمیم و تاریخچه. هر تصمیم پیش از ثبت یک بار تأیید می‌خواهد؛ اگر برای تصمیمی (مثلاً «رد») یادداشت الزامی باشد، بی یادداشت ثبت نمی‌شود.
  - **تأیید از ایمیل:** اگر اعلان کار تازه را با ایمیل می‌گیرید و «نشانی سامانه» در تنظیمات پیامک و ایمیل پر است، در ایمیل پیوند «تأیید» (برای تصمیم‌های بی یادداشت الزامی) می‌آید؛ پیوند را باز کنید و «ثبت» را بزنید. پیوند یک‌بارمصرف است و اعتبارش (پیش‌فرض سه روز) در «تنظیمات › سامانه و امنیت» است.
  - **همه‌ی گیرنده‌ها:** اگر در فرایندساز «تصمیم با» روی «همه‌ی گیرنده‌ها» باشد، کار در «منتظر من» همه می‌آید و هر کدام نظر می‌دهد؛ نظر هر نفر در صفحه‌ی کار دیده می‌شود. کار وقتی تأیید می‌شود که همه موافق باشند؛ یک «رد» کافی است.
  - **گفت‌وگو:** برای پرسش و پاسخ پیش از تصمیم (مثلاً «پیش‌فاکتور دوم را هم بفرستید»)؛ درخواست‌دهنده و همه‌ی گیرنده‌ها پیام‌ها را می‌بینند و اعلان می‌گیرند.
- **ثبت‌های من:** همه‌ی فرم‌هایی که پر کرده‌اید و پیش‌نویس‌ها، با جست‌وجو (عنوان فرم یا شماره) و فیلتر وضعیت. پیش‌نویس را ادامه دهید؛ ثبت نهایی را ببینید، **چاپ** کنید (در پنجره‌ی چاپ «ذخیره به‌صورت PDF» هم هست) و اگر فرم اجازه دهد تا پایان مهلت ویرایش کنید.
### برای مدیران و بینندگان

- **پرونده‌ی من** (منوی «منابع انسانی»، برای کارمندی که پرونده‌اش به حساب کاربری‌اش وصل است): پرونده‌ی خودتان با همه‌ی زبانه‌ها، فقط‌خواندنی، با مانده‌ی مرخصی و درخواست‌ها و نامه‌هایتان. برای اصلاح، دکمه‌ی «درخواست اصلاح» (اگر فرایند آماده‌ی «اصلاح اطلاعات پرونده» فعال باشد) را بزنید.
- **پرونده‌های پرسنلی** (منوی «منابع انسانی»؛ دارندگان مجوز «دیدن» یا «ثبت و ویرایش پرونده‌های پرسنلی»، و مدیر هر واحد برای کارکنان واحد خود و زیرواحدهایش، فقط‌خواندنی): جدول کارکنان با جست‌وجوی نام، کد پرسنلی یا کد ملی، فیلتر واحد، نوع استخدام و وضعیت، و «خروجی کامل اکسل».
  - **ورود از اکسل** (ثبت‌کنندگان پرونده): «فایل نمونه» را بگیرید و پر کنید؛ فایل اکسل یا CSV را انتخاب کنید، جفت شدن ستون‌ها با فیلدهای پرونده را ببینید، «پیش‌نمایش» خطای هر ردیف را نشان می‌دهد و فقط ردیف‌های درست ثبت می‌شوند. کد ملی کلید است: کد ملی موجود همان پرونده را به‌روز می‌کند.
  - **گزارش نیروی انسانی:** ترکیب کارکنان شاغل (واحد، نوع استخدام، مقطع تحصیلی، جنسیت، گروه سنی)، ورود و خروج در بازه‌ی دلخواه، و مدارک گذشته یا نزدیک به پایان اعتبار؛ هر بخش با نمودار، جدول و خروجی اکسل. مدیر واحد فقط آمار واحد خودش را می‌بیند.
  - **پرونده‌ی تازه:** نام، کد ملی، جنسیت، تاریخ و نوع استخدام کافی است؛ کد پرسنلی خودکار صادر می‌شود (الگویش در «تنظیمات › شماره‌گذاری اسناد»). اگر کارمند حساب کاربری دارد، «کاربر سامانه» را انتخاب کنید تا سمت‌هایش از ساختار سازمانی خوانده شود و کد ملی‌اش در فرم‌ها پیش‌پر شود.
  - **صفحه‌ی پرونده:** زبانه‌های «مشخصات»، «استخدام» (با سمت‌های جاری، پایان دوره‌ی آزمایشی و پایان قرارداد)، «درخواست‌ها و نامه‌ها» (نتیجه‌ی درخواست‌های تأییدشده، مانده‌ی مرخصی و نامه‌های صادرشده با پیوند چاپ)، «اطلاعات تکمیلی»، «تحصیلات و سوابق کاری»، «خانواده»، «بانک و بیمه» و «مدارک»؛ در هر زبانه‌ی سوابق «افزودن»، و از منوی هر ردیف ویرایش یا حذف. «بانک و بیمه» را مدیر واحد نمی‌بیند. مدرکی که تاریخ اعتبارش گذشته «منقضی» نشان داده می‌شود؛ «ویرایش پرونده» برای تغییر یا «پایان همکاری» (با تاریخ و علت). پرونده حذف نمی‌شود تا سوابقش بماند.
- **ثبت‌های فرم‌ها** (طراحان فرم و دارندگان «نقش‌های بیننده»ی هر فرم): فهرست فرم‌ها با شمار ثبت‌ها؛ با باز کردن هر فرم، جدول ثبت‌های نهایی با یک ستون برای هر فیلد (ستون‌های بیشتر از «نما»)، جست‌وجو در همه‌ی ستون‌ها، فیلتر گزینه‌ها و «خروجی اکسل» از همان ستون‌ها و ردیف‌های فیلترشده؛ هر ردیف به صفحه‌ی مشاهده و چاپ می‌رود.
- **مدیریت درخواست‌ها** («مدیران فرایند» در مشخصات هر فرایند، و دارندگان مجوز «مدیریت همه‌ی درخواست‌ها» برای همه‌ی فرایندها): زبانه‌های «در جریان»، «بی‌گیرنده»، «دیرکرده» و «همه». با باز کردن هر درخواست، بخش «مدیریت درخواست» می‌آید؛ هر کار دلیل می‌خواهد که در تاریخچه ثبت می‌شود:
  - **ارجاع دوباره:** کار منتظر را به همکار دیگری بدهید (مثلاً گیرنده در مرخصی است).
  - **ارسال به مرحله‌ی گذشته:** درخواست به یکی از مرحله‌های انجام‌شده برمی‌گردد. پرش به مرحله‌ای که هنوز نرسیده ممکن نیست؛ برای جلو بردن، کار را ارجاع دهید.
  - **شروع دوباره:** فرایند با داده‌ی فعلی درخواست از آغاز اجرا می‌شود (مثلاً پس از اصلاح فرایند یا ساختار سازمانی).
  - **لغو با دلیل:** در هر مرحله؛ گیرنده‌های منتظر و درخواست‌دهنده اعلان می‌گیرند.
- **گزارش عملکرد** (همان مدیران): بازه (پیش‌فرض ۹۰ روز اخیر) و فرایند را انتخاب کنید. «خلاصه» شمار درخواست‌ها، میانگین و بیشترین زمان و کارهای دیرکرده را نشان می‌دهد. زمان‌ها به **ساعت کاری** است (شب‌ها و تعطیلات «روزها و ساعت کاری» شمرده نمی‌شوند).
  - **مرحله‌ها و گلوگاه‌ها:** کندترین مرحله‌ها بالای نمودار؛ اینها جایی است که درخواست‌ها بیشتر می‌مانند.
  - **افراد** و **واحدها:** کار انجام‌شده، کار منتظر، میانگین زمان و دیرکرد هر نفر و هر واحد؛ نمودار کارهای منتظر هر نفر بار کاری فعلی را نشان می‌دهد.
  - هر جدول «خروجی اکسل» دارد.

### برای طراحان فرم و فرایند

- **طراحی فرایندها** (دارندگان مجوز «طراحی فرایندها»): «فرایند جدید» روی یک فرم منتشرشده. در بوم:
  - از نوار ابزار کنار بوم عنصر بکشید؛ روی یک مسیر رها کنید تا میان دو مرحله قرار گیرد.
  - یا روی یک عنصر بزنید و از منوی کنارش مرحله‌ی بعد را بیفزایید. با دوبار زدن عنوان بنویسید.
  - همه‌چیز خودکار ذخیره می‌شود. ایرادها با کادر قرمز روی عنصر و در فهرست «ایرادهای انتشار» می‌آیند؛ با زدن هر ایراد به همان عنصر می‌روید.
  - «انتشار» وقتی فعال است که ایرادی نباشد. نسخه‌ی منتشرشده فقط‌خواندنی است و «ویرایش فرایند» پیش‌نویس تازه می‌سازد.
  - **پانل ویژگی‌ها** (روی لپ‌تاپ با دکمه‌ی «ویژگی‌های عنصر»). با انتخاب هر عنصر:
    - **کار کاربری:** عنوان؛ گیرنده (خود درخواست‌دهنده، مدیر مستقیم، مدیر یک واحد، صاحب سمت، دارندگان نقش، کاربر مشخص، کاربر انتخاب‌شده در فرم، یا «نقش تعیین‌شده در تنظیمات» مثل منابع انسانی که یک بار در تنظیمات تعیین می‌شود)؛ «تصمیم با» یکی از گیرنده‌ها (کار گروهی) یا همه‌ی گیرنده‌ها (هر کدام نظر می‌دهد؛ یک «رد» کافی است)؛ دکمه‌های تصمیم و یادداشت الزامی؛ تأیید خودکار وقتی گیرنده همان نفر مرحله‌ی قبل است؛ **مهلت انجام** به روز یا ساعت کاری با یادآوری و کار پس از پایان مهلت (اعلان به مدیر، ارجاع به دیگری، یا تأیید/رد خودکار)؛ **متن اعلان این مرحله** با مقدار فیلدها (مثلاً «درخواست {subject} به مبلغ {amount} ریال رسید»)؛ و اینکه هر فیلد فرم در این مرحله پنهان، فقط‌خواندنی، قابل ویرایش یا الزامی باشد.
    - **مسیر خروجی دروازه‌ی شرطی:** «مسیر پیش‌فرض» یا شرط با همان سازنده‌ی فرم‌ساز (مثلاً «تصمیم مرحله‌ی قبل برابر است با تأیید»).
    - **مرحله‌ی زمان‌بندی** (آیکون ساعت): صبر چند روز یا ساعت کاری، یا تا تاریخی از فرم، و سپس ادامه‌ی خودکار.
    - **اقدام خودکار:** «تنظیم مقدار فیلد»، «اعلان یا ایمیل» (به هر گیرنده، با مقدار فیلدها در متن)، یا «ثبت در فرم دیگر» (هر فیلد فرم مقصد را به فیلدی از فرم اصلی وصل کنید؛ ثبت تازه به نام درخواست‌دهنده یا به‌روزرسانی ثبتی که در درخواست انتخاب شده)؛ با ماژول پرسنلی: ثبت در پرونده، صدور نامه، استخدام، تغییر سمت یا واحد، اصلاح پرونده، پایان همکاری و بررسی سقف تأیید مدیرعامل.
    - **رویداد پایان:** نتیجه‌ی درخواست («انجام شد» یا «رد شد»).
  - **مشخصات:** چه کسانی درخواست شروع کنند، مدیران فرایند (کار بی‌گیرنده به آن‌ها می‌رسد)، چه نقش‌هایی درخواست را به نام دیگری ثبت کنند، الگوی شماره‌ی درخواست.
  - **نسخه‌ها:** خروجی فایل BPMN هر نسخه، دیدن دو نسخه کنار هم، و ورود فایل BPMN به پیش‌نویس.
  - **«الگوی درخواست خرید»:** فرم و فرایند سه‌مرحله‌ای آماده می‌سازد؛ فقط گیرنده‌ی «مدیر مالی» و «تدارکات» را تعیین کنید و منتشر کنید.
  - روی موبایل فقط نمودار دیده می‌شود. نشان کوچک bpmn.io گوشه‌ی بوم، شرط مجوز ابزار بوم است ([مجوز کتابخانه‌های متن‌باز](docs/THIRD-PARTY-NOTICES.md)).
- **طراحی فرم‌ها** (دارندگان مجوز «طراحی فرم‌ها»):
  - **ساخت فرم:** «فرم جدید» (خالی)، «فرم جدید از الگو» یا «ورود فرم» از فایلی که با «خروجی فرم» ساخته شده (برای انتقال فرم بین دو نصب نیک‌یار). منوی هر فرم: طراحی، ثبت‌ها، تنظیمات، کپی، خروجی فرم، حذف.
  - **تنظیمات فرم** (دکمه‌ی «تنظیمات»): دسته، چه کسانی پر کنند، چه نقش‌هایی همه‌ی ثبت‌ها را ببینند، فعال/غیرفعال، الگوی شماره‌ی ثبت؛ «پذیرش و محدودیت‌ها» (بازه‌ی پذیرش، ظرفیت، سقف ثبت هر نفر، ویرایش پس از ثبت، پیش‌نویس)؛ «پس از ثبت» (بازگشت، صفحه‌ی تأیید یا نشانی؛ اعلان به ثبت‌کننده و به کاربران و نقش‌ها)؛ «حریم» (بی‌نام). این تنظیمات بی‌نیاز به انتشار فوری اثر می‌کنند.
  - **جعبه‌ابزار:** بلوک‌های آماده (مشخصات فردی، اطلاعات تماس، نشانی، حساب بانکی) و همه‌ی نوع فیلدها؛ با کلیک پس از فیلد انتخاب‌شده اضافه می‌شوند یا روی صفحه‌ی پهن روی بوم کشیده می‌شوند. وقتی یک گروه تکرارشونده یا فیلدی از آن انتخاب شده، نوع تازه درون همان گروه می‌رود.
  - **چیدمان:** در سربرگ هر بخش روی بوم «۱ / ۲ / ۳ ستون» را بزنید؛ دکمه‌ی پهنا در نوار ابزار هر فیلد آن را یک، دو ستون یا تمام عرض می‌کند؛ «شروع از ردیف تازه» و «جای برچسب» در پانل ویژگی‌هاست. روی موبایل همه‌چیز یک ستون است.
  - **بوم و ویژگی‌ها:** با زدن هر فیلد، ویژگی‌هایش (برچسب، راهنما، الزامی، فقط‌خواندنی، مقدار پیش‌فرض، پیش‌پر از حساب کاربر، مقدار یکتا، گزینه‌ها و…) در پانل «ویژگی‌ها» باز می‌شود. جابه‌جایی با کشیدن دستگیره، صفحه‌کلید (Space و کلیدهای جهت) یا دکمه‌های بالا/پایین.
  - **ویژگی‌های فرم** (دکمه‌ی بالای بوم): نمایش مرحله‌ای، شماره‌گذاری فیلدها، نشانه‌ی الزامی، متن دکمه‌ی ثبت، متن آغاز فرم، پیام پس از ثبت (با {شماره}، {نام}، {تاریخ}، {فرم})، و اعتبارسنجی بین فیلدها.
  - **قاعده‌ها** (پانل ویژگی‌ها، بخش «قاعده‌ها»): «نمایش شرطی»، «الزامی شرطی» و «فقط‌خواندنی شرطی» با جمله‌هایی مثل «نوع مرخصی برابر است با استعلاجی» و «گروه شرط» برای ترکیب «و» و «یا»؛ فیلد **محاسبه‌ای** (جمع، تفاضل، ضرب، تقسیم، شمار روز، جمع یک گروه تکرارشونده مثل تعداد × فی).
  - **فیلدهای دلخواه پرونده‌ی پرسنلی:** در صفحه‌ی یک پرونده، زبانه‌ی «اطلاعات تکمیلی» › «طراحی فیلدها» همین طراح را برای فیلدهای پرونده باز می‌کند؛ پس از «انتشار»، فیلدها در همه‌ی پرونده‌ها و جدول پرونده‌ها می‌آیند.
  - هر تغییر خودکار ذخیره می‌شود؛ ایراد تعریف با کادر قرمز و پیام در پانل نشان داده می‌شود. واگرد و ازنو با دکمه‌ها یا `Ctrl+Z` و `Ctrl+Y`.
  - **پیش‌نمایش:** فرم در اندازه‌ی رایانه یا موبایل با قاعده‌ها و «آزمایش ثبت»، بی ذخیره.
  - **انتشار و نسخه‌ها:** «انتشار» نسخه را برای پرکنندگان فعال می‌کند؛ «ویرایش فرم» پیش‌نویس تازه می‌سازد و ثبت‌های گذشته با نسخه‌ی خودشان می‌مانند. «نسخه‌ها» تاریخچه، خروجی هر نسخه و مقایسه‌ی دو نسخه را نشان می‌دهد.
  - روی لپ‌تاپ و موبایل، جعبه‌ابزار و ویژگی‌ها در پانل کناری باز می‌شوند (دکمه‌های «افزودن فیلد» و «ویژگی‌ها»).

### نکته‌های کار با سامانه

- **جست‌وجوی سراسری:** `Ctrl+K` (یا ذره‌بین نوار بالا) و نوشتن نام بخش.
- **پوسته‌ی تیره:** نماد نمایشگر در نوار بالا.
- **زبانه‌ها:** هر صفحه‌ای که باز می‌کنید زبانه می‌شود؛ با یک کلیک برمی‌گردید و با × می‌بندید.
- **جدول‌ها:** جست‌وجو، فیلتر، مرتب‌سازی (Shift برای چند ستون)؛ از منوی سرستون: سنجاق کردن ستون به ابتدا یا انتها و پنهان‌کردن؛ از «نما»: ستون‌های نمایان، تراکم ردیف‌ها و بازگشت به نمای پیش‌فرض؛ تغییر عرض ستون با کشیدن لبه‌ی سرستون؛ «خروجی اکسل». این انتخاب‌ها برای هر کاربر در همان مرورگر می‌مانند.
- **تاریخ‌ها:** تاریخ را مستقیم تایپ کنید (`14050816` خودش `1405/08/16` می‌شود) یا از تقویم انتخاب کنید؛ روزهای تعطیل قرمزند.
- **راهنمای ⓘ:** کنار برچسب‌ها و عنوان‌ها؛ با نگه داشتن نشانگر یا زدن (موبایل) باز می‌شود.

## پشتیبان‌گیری و بازیابی

- تا وقتی پنجره‌ی `start.bat` باز است، سامانه هر روز (پیش‌فرض ساعت ۰۲:۰۰) **پشتیبان کامل** (همه‌ی اطلاعات و فایل‌ها) می‌گیرد؛ اگر آن ساعت خاموش بوده، در اولین روشن شدن. چند نسخه‌ی آخر نگه داشته می‌شود (پیش‌فرض ۷).
- فایل‌های پشتیبان در `backend\data\backups` هستند و از «نگه‌داری سامانه › پشتیبان‌گیری» دانلود می‌شوند. **گاهی یک نسخه را روی فلش یا رایانه‌ی دیگری هم نگه دارید**؛ پشتیبانی که روی همان دیسک است با خرابی دیسک از بین می‌رود.
- **بازیابی:** از فهرست، یا «بازیابی از فایل» برای فایلی که روی رایانه‌ی شماست. برای تأیید باید نام سازمان را بنویسید. پیش از بازیابی از وضع فعلی خودکار پشتیبان «پیش از بازیابی» گرفته می‌شود تا در صورت اشتباه برگردید.
- پشتیبانِ نسخه‌ی جدیدتر نیک‌یار روی نسخه‌ی قدیمی‌تر بازیابی نمی‌شود؛ ابتدا `update.bat`.
- پشتیبان هر دو نوع پایگاه داده (SQLite یا PostgreSQL) روی دیگری هم بازیابی می‌شود.

### پایگاه داده‌ی PostgreSQL (سازمان‌های بزرگ‌تر)

پایگاه داده‌ی درونی (SQLite) برای بیشتر سازمان‌ها کافی است. برای سازمان‌های بزرگ‌تر، راهبر شبکه PostgreSQL (نسخه‌ی ۱۴ یا بالاتر) را نصب و یک پایگاه و کاربر خالی برای نیک‌یار می‌سازد؛ سپس:

1. پنجره‌ی `start.bat` را ببندید (یا سرویس را از `service.bat` متوقف کنید).
2. `database-tool.bat` را دو بار کلیک کنید و گزینه‌ی ۱ را بزنید؛ نشانی، درگاه، نام پایگاه، کاربر و گذرواژه را بدهید و `YES` بنویسید.
3. ابزار از وضع فعلی پشتیبان «پیش از تغییر پایگاه داده» می‌گیرد، پایگاه تازه را می‌سازد و همه‌ی اطلاعات را منتقل می‌کند. اگر جایی خطا رخ دهد، هیچ چیز عوض نمی‌شود و سامانه با پایگاه قبلی کار می‌کند.
4. `start.bat` را دوباره اجرا کنید (یا سرویس را روشن کنید).

ساخت کاربر و پایگاه خالی در PostgreSQL: [راهنمای نصب، بخش ۵](docs/INSTALL.md).

بازگشت به پایگاه درونی با گزینه‌ی ۲ همان ابزار است. گزینه‌ی ۳ یک فایل پشتیبان را بی‌نیاز به ورود به سامانه بازیابی می‌کند (برای پایگاه تازه‌ای که هنوز کاربری ندارد). تنظیم اتصال در `backend\data\database.json` نگه داشته می‌شود.

## پیامک و ایمیل

در «پیکربندی › تنظیمات › پیامک و ایمیل»:

- **پیامک (کاوه‌نگار):** در پنل کاوه‌نگار کلید API و شماره‌ی خط را بردارید و وارد کنید. سرور برای پیامک به اینترنت نیاز دارد. هزینه‌ی پیامک را سازمان مستقیم به درگاه می‌پردازد.
- **ایمیل (مثلاً Gmail):** سرور `smtp.gmail.com`، درگاه ۵۸۷، STARTTLS، نام کاربری همان نشانی Gmail، و به‌جای گذرواژه‌ی حساب یک «App password» از تنظیمات امنیتی حساب گوگل.
- **نشانی سامانه:** همان نشانی که `start.bat` نشان می‌دهد؛ ایمیل‌ها با آن پیوند صفحه‌ی مرتبط و پیوندهای «تأیید با یک کلیک» کارتابل را می‌سازند.
- پس از ذخیره، «ارسال آزمایشی» را بزنید؛ نتیجه و هر خطا در «گزارش ارسال‌ها» دیده می‌شود.
- **پیش‌فرض‌ها:** «تغییر گذرواژه» با پیامک و ایمیل؛ «ساخت حساب»، «جانشینی» و «خطای کار سامانه» با ایمیل؛ بقیه (از جمله «کار تازه در کارتابل») فقط درون سامانه. سازمان در «تنظیمات › متن اعلان‌ها» و هر کاربر در «حساب من › اعلان‌ها» تغییرش می‌دهد.
- کلید و گذرواژه رمزشده نگهداری و هرگز نمایش داده نمی‌شوند.

## لایسنس

- هر نصب **۳۰ روز آزمایشی** کار می‌کند (تا ۵۰ کاربر فعال). پس از آن بدون لایسنس معتبر سامانه **فقط‌خواندنی** می‌شود: اطلاعات پاک نمی‌شود، پشتیبان‌گیری و بارگذاری لایسنس کار می‌کند، ولی ثبت و ویرایش نه.
- لایسنس فایل `‎.nikyar-license` است که صادرکننده برای «شناسه‌ی نصب» همان سرور امضا می‌کند و سقف کاربران فعال، ماژول‌ها و تاریخ اعتبار در آن است. هر دست‌کاری در فایل آن را باطل می‌کند.
- ۳۰ روز پیش از پایان اعتبار، نوار هشدار به راهبر سامانه نشان داده می‌شود.
- **برای مالک محصول:** ساخت کلید و صدور لایسنس با دوبار کلیک روی `license-tool.bat`؛ راهنمای کامل: [docs/LICENSE-GUIDE.md](docs/LICENSE-GUIDE.md). کلید خصوصی را روی فلش هم نگه دارید و به کسی ندهید.

## داده‌ها کجا هستند

همه‌ی داده‌های هر نصب در `backend\data`:

| مسیر | محتوا | نکته |
|---|---|---|
| `nikyar.db` | پایگاه داده‌ی درونی (همه‌ی اطلاعات، اگر PostgreSQL به کار نرود) | فقط با پشتیبان‌گیری کپی کنید، نه کپی دستی هنگام کار سامانه |
| `database.json` | اتصال PostgreSQL (ساخته‌ی `database-tool.bat`) | گذرواژه‌ی پایگاه در آن است؛ نبودنش یعنی پایگاه درونی |
| `media\` | فایل‌های بارگذاری‌شده (لوگو، امضا، پیوست‌ها، صدا، تصویر و فایل راهنمای فرم‌ها) | |
| `backups\` | فایل‌های پشتیبان | یک نسخه را بیرون از این رایانه هم نگه دارید |
| `secret_key` | کلید امنیتی همین نصب | پاک نکنید: ورود همه‌ی کاربران باطل و کلید پیامک/ایمیل ناخوانا می‌شود |
| `install_id` | شناسه‌ی نصب برای لایسنس | پاک نکنید: لایسنس دیگر با این نصب جور نیست |
| `setup_code` | کد راه‌اندازی نخستین | فقط تا پایان راه‌اندازی هست و سپس خودکار پاک می‌شود |
| `static\` | فایل‌های ظاهری صفحه‌های داخلی Django | خودکار با نصب و به‌روزرسانی ساخته می‌شود |

`update.bat` هرگز به این پوشه دست نمی‌زند.

## پرسش‌های متداول

### نصب و اجرا

**`install.bat` می‌گوید Python مناسب پیدا نشد.**
Python 3.13 را از python.org نصب کنید (کنار نسخه‌های دیگر هم می‌تواند باشد) و دوباره `install.bat` را اجرا کنید. نسخه‌ی ۳٫۱۵ هنوز پشتیبانی نمی‌شود.

**چرا پنجره‌ی `start.bat` باید باز بماند؟**
خود سامانه در همان پنجره اجرا می‌شود. با بستن آن، سامانه برای همه از دسترس خارج می‌شود و کارهای خودکار (پشتیبان روزانه، ارسال پیامک) هم انجام نمی‌شوند. برای کار بدون پنجره، سامانه را با `service.bat` سرویس ویندوز کنید.

**سرویس را نصب کرده‌ام؛ کد راه‌اندازی کجاست؟**
`service.bat` گزینه‌ی ۵.

**`update.bat` خطای «would be overwritten by merge» می‌دهد.**
فایلی در پوشه‌ی پروژه به‌جز `backend\data` تغییر کرده یا اضافه شده است. در پوشه‌ی پروژه چیزی را دستی ویرایش نکنید. نام فایل در پیام آمده است؛ اگر نمی‌دانید چیست، پیام را برای پشتیبانی بفرستید.

**موبایل یا رایانه‌ی دیگر وصل نمی‌شود.**
هر دو باید در یک شبکه باشند؛ «Allow» در پرسش دیوار آتش یا اجرای `allow-network.bat` با دسترسی Administrator؛ و نوع شبکه‌ی وای‌فای ویندوز «Private». نشانی را دقیقاً همان‌که `start.bat` نشان می‌دهد وارد کنید (با `:8000`).

**نشانی سامانه هر روز عوض می‌شود.**
مودم هر بار نشانی تازه به سرور می‌دهد. در تنظیمات مودم برای این رایانه «IP ثابت» (DHCP reservation) تعیین کنید.

**می‌توانم سامانه را روی اینترنت بگذارم؟**
فعلاً نه؛ نیک‌یار برای شبکه‌ی داخلی سازمان است. اتصال امن (HTTPS) و سخت‌گیری‌های امنیتی بیشتر در نسخه‌ی ۱٫۰ اضافه می‌شود.

### کاربران و ورود

**گذرواژه را فراموش کرده‌ام.**
راهبر سامانه در «کاربران» گذرواژه‌ی تازه می‌گذارد (اعلان و پیامک آن به کاربر می‌رسد). اگر گذرواژه‌ی `admin` فراموش شده، در پوشه‌ی پروژه این فرمان را اجرا کنید:
```
.venv\Scripts\python backend\manage.py changepassword admin
```

**چرا نمی‌توانم کاربر تازه بسازم؟**
سقف کاربران فعال لایسنس (یا دوره‌ی آزمایشی) پر است. کاربرانی را که کار نمی‌کنند غیرفعال کنید یا لایسنس با کاربر بیشتر بگیرید.

**چرا کاربر حذف نمی‌شود؟**
برای حفظ سوابق (چه کسی چه کاری کرده)، کاربر فقط غیرفعال می‌شود و دیگر نمی‌تواند وارد شود.

**پیام «اعتبار لایسنس تمام شده و فقط مشاهده ممکن است» یعنی چه؟**
دوره‌ی آزمایشی یا لایسنس تمام شده است. اطلاعات محفوظ است؛ راهبر سامانه لایسنس تازه را در «ماژول‌ها و لایسنس» بارگذاری کند.

### اعلان، پیامک و ایمیل

**پیامک یا ایمیل اعلان نمی‌رسد.**
به ترتیب بررسی کنید: «تنظیمات › پیامک و ایمیل» تنظیم و «ارسال آزمایشی» موفق باشد؛ کاربر در «حساب من» موبایل/ایمیل داشته باشد و آن کانال را برای آن نوع اعلان روشن کرده باشد؛ پنجره‌ی `start.bat` باز باشد؛ و در «گزارش ارسال‌ها» خطای ارسال را ببینید.

**متن اعلان‌ها را چطور تغییر دهم؟**
«تنظیمات › متن اعلان‌ها»؛ جای‌گذارها (مثل نام کاربر) با دکمه درج می‌شوند و پیش‌نمایش زنده دارند.

### تقویم، شماره و فایل

**تعطیلات سال آینده ثبت نشده است.**
در «تقویم کاری» به سال بعد بروید و «افزودن تعطیلات رسمی» را بزنید. اگر تقویم رسمی آن سال هنوز در نیک‌یار نیست، تعطیلات ثابت شمسی اضافه می‌شود و تعطیلات قمری را دستی یا با «ورود از فایل» (CSV اکسل) اضافه کنید.

**شماره‌ی اسناد را از شماره‌ی سامانه‌ی قبلی ادامه دهم؟**
«تنظیمات › شماره‌گذاری اسناد»، ویرایش الگو، و «شماره‌ی بعدی». فقط بیشتر از آخرین شماره‌ی صادرشده پذیرفته می‌شود تا شماره تکراری نشود.

**فایل بارگذاری نمی‌شود.**
حجم یا نوع آن مجاز نیست؛ پیام دلیل را می‌گوید. سقف حجم و نوع‌ها در «تنظیمات › فایل‌ها و پیوست‌ها» تغییر می‌کند. فایل‌های خطرناک (مثل SVG، HTML و برنامه‌ها) و فایلی که محتوایش با پسوندش نمی‌خواند هرگز پذیرفته نمی‌شوند.

### پشتیبان و انتقال

**سرور خراب شد؛ چطور روی رایانه‌ی تازه برگردانم؟**
روی رایانه‌ی تازه نیک‌یار را نصب کنید، در «پشتیبان‌گیری › بازیابی از فایل» آخرین فایل پشتیبان را بارگذاری کنید. سپس: لایسنس تازه برای شناسه‌ی نصب جدید بگیرید، و کلید پیامک و گذرواژه‌ی ایمیل را دوباره وارد کنید (رمزشان به همان نصب قبلی بسته بود).

**می‌خواهم از صفر و بدون داده‌ی نمونه شروع کنم.**
در جادوگر «راه‌اندازی نخستین» گزینه‌ی «راه‌اندازی سازمان» را بزنید؛ سامانه خالی و فقط با حساب راهبر شما شروع می‌شود. اگر پیش‌تر نسخه‌ی نمایشی ساخته‌اید، برای شروع از صفر پایگاه داده‌ی خالی لازم است (با پشتیبانی هماهنگ کنید؛ پشتیبان بگیرید).

**کد راه‌اندازی را گم کرده‌ام / پنجره بسته شد.**
`start.bat` را دوباره اجرا کنید؛ تا راه‌اندازی تمام نشده، همان کد دوباره در پنجره چاپ می‌شود (در `backend\data\setup_code` هم هست).

**چند کاربر را پشتیبانی می‌کند؟**
برای ۱۰ تا ۵۰۰ کاربر طراحی شده است. پایگاه داده‌ی درونی (SQLite) برای سازمان‌های کوچک و متوسط کافی است؛ سازمان‌های بزرگ‌تر با `database-tool.bat` به PostgreSQL می‌روند (بخش «پایگاه داده‌ی PostgreSQL»). آزمون بار ۵۰۰ کاربر در نسخه‌ی ۱٫۰ می‌آید.

### فرم‌ها

**فرمی در صفحه‌ی «فرم‌ها» نیست.**
فرم باید منتشر شده و فعال باشد، و شما در «تنظیمات» آن جزو پرکنندگان باشید («همه‌ی کاربران پر کنند» یا یکی از نقش‌های پرکننده).

**دکمه‌ی ثبت غیرفعال است.**
پیام بالای فرم دلیل را می‌گوید: هنوز باز نشده، مهلتش تمام شده، ظرفیتش پر شده یا سقف ثبت شما پر شده است (تنظیمات فرم › پذیرش و محدودیت‌ها).

**ثبت نهایی را اشتباه زدم.**
اگر فرم «ویرایش پس از ثبت» دارد، از صفحه‌ی تأیید یا «ثبت‌های من» «ویرایش» را بزنید؛ در غیر این صورت ثبت نهایی تغییر نمی‌کند (برای همین پیش از ثبت پنجره‌ی مرور می‌آید).

**ثبت‌های یک فرم را چه کسی می‌بیند؟**
هر کس ثبت‌های خودش را در «ثبت‌های من»؛ طراحان فرم همه‌ی ثبت‌های نهایی؛ و دارندگان «نقش‌های بیننده» در تنظیمات همان فرم، ثبت‌های نهایی آن فرم را در «ثبت‌های فرم‌ها». پیش‌نویس فقط برای خود ثبت‌کننده است و در فرم بی‌نام نام ثبت‌کننده دیده نمی‌شود.

**لوگوی برگه‌ی چاپ را کجا تعیین کنم؟**
تنظیمات › مشخصات سازمان (نام و لوگو)؛ برگه‌ی چاپ همان را نشان می‌دهد.

**فرم را به نصب دیگری از نیک‌یار ببرم؟**
در «طراحی فرم‌ها» از منوی فرم «خروجی فرم» بگیرید و در نصب دیگر «ورود فرم» را بزنید؛ تصویرها و فایل‌های راهنما هم همراه‌اند. دسترسی‌ها را آنجا دوباره تعیین کنید.

### پرونده‌ی پرسنلی و فرایندهای آماده

**بخش «منابع انسانی: نقش‌ها و سقف مبلغ» در تنظیمات برای چیست؟ مگر گیرنده‌ی هر مرحله را فرایندساز تعیین نمی‌کند؟**
هر دو درست است. مرحله‌های فرایندهای آماده به «نقش منابع انسانی (یا امور مالی، مدیرعامل…) تعیین‌شده در تنظیمات» می‌روند، نه به نام یک نقش مشخص؛ چون نیک‌یار از پیش نمی‌داند این نقش در سازمان شما «کارگزینی» نام دارد یا «امور اداری». شما یک بار در تنظیمات می‌گویید کدام نقش است و همه‌ی فرایندها همان را به کار می‌برند؛ با جابه‌جایی کار به نقش دیگر هم فقط همان یک‌جا را عوض می‌کنید. «سقف مبلغ» هم همین‌طور: بالاتر از آن، تأیید مدیرعامل لازم است. اگر برای فرایندی گیرنده‌ی دیگری بخواهید، همان مرحله را در فرایندساز تغییر دهید؛ فقط همان فرایند عوض می‌شود.

**«فعال‌سازی همه» یکی از فرایندها را فعال نکرد.**
پیام دلیل را می‌گوید؛ معمولاً نقشی که آن فرایند لازم دارد (مثلاً نقش منابع انسانی برای «استخدام») در «تنظیمات › منابع انسانی: نقش‌ها و سقف مبلغ» تعیین نشده است. پس از تعیین، دوباره «فعال‌سازی» را بزنید.

**مانده‌ی مرخصی چطور حساب می‌شود؟**
سهمیه‌ی سال شمسی جاری (بر پایه‌ی نوع استخدام و، برای تازه‌واردها، سهم ماه‌های کارکرد) به‌علاوه‌ی مانده‌ی منتقل‌شده از سال قبل تا سقف انتقال، منهای مرخصی‌های کسرشونده‌ی تأییدشده؛ مرخصی ساعتی به نسبت «مدت هر روز مرخصی» کم می‌شود. همه در «تنظیمات › منابع انسانی: مرخصی و تردد».

**فرایند آماده را تغییر دادم؛ با به‌روزرسانی نیک‌یار پاک می‌شود؟**
نه. پس از فعال‌سازی، فرم و فرایند مال سازمان شماست و به‌روزرسانی هرگز آن‌ها را بازنویسی نمی‌کند.

### گردش کار و کارتابل

**کاری به کسی نرسید (مثلاً واحد مدیر ندارد).**
کار به «مدیران فرایند» (مشخصات فرایند) و اگر تعیین نشده‌اند به مدیر کل سپرده می‌شود و هشدار اعلان می‌شود؛ ساختار سازمانی یا گیرنده‌ی مرحله را درست کنید.

**دکمه‌ی «لغو درخواست» نیست.**
لغو فقط برای درخواست‌دهنده و تا وقتی ممکن است که هیچ مرحله‌ای تصمیم نگرفته باشد. پس از آن، مدیر فرایند می‌تواند در «مدیریت درخواست‌ها» با دلیل لغو کند. اگر خودتان مدیر فرایند هستید، به جای این دکمه «لغو با دلیل» را در بخش «مدیریت درخواست» می‌بینید.

**پیوند «تأیید» در ایمیل نمی‌آید.**
«نشانی سامانه» در تنظیمات پیامک و ایمیل پر باشد، گیرنده ایمیل «کار تازه در کارتابل» را در «حساب من › اعلان‌ها» روشن کرده باشد، و تصمیم یادداشت الزامی نداشته باشد (مثلاً «رد» با یادداشت الزامی پیوند ندارد).

**مهلت یا مرحله‌ی زمان‌بندی دیر اجرا شد.**
بررسی هر ۵ دقیقه و فقط وقتی پنجره‌ی `start.bat` باز است انجام می‌شود؛ روز و ساعت کاری از «تنظیمات › روزها و ساعت کاری» و «تقویم کاری» است.

**فرایند را تغییر دادم؛ درخواست‌های در جریان چه می‌شوند؟**
هر درخواست تا پایان روی نسخه‌ای می‌ماند که با آن شروع شده؛ نسخه‌ی تازه فقط برای درخواست‌های تازه است.

**پرونده‌ی پرسنلی کی می‌آید؟**
در نسخه‌ی ۰٫۶ (فاز ۵: پرونده‌ی پرسنلی و فرایندهای آماده مثل مرخصی). جزئیات در [نقشه‌ی راه](docs/ROADMAP.md).

## برای توسعه

```bash
python -m venv .venv && .venv/bin/pip install -r backend/requirements-dev.txt
cd frontend && npm ci
```

| کار | فرمان |
|---|---|
| اجرای سرور API | `cd backend && ../.venv/bin/python manage.py runserver` |
| اجرای کارهای پس‌زمینه در توسعه | `cd backend && ../.venv/bin/python manage.py run_worker` |
| اجرای رابط کاربری (با بارگذاری خودکار) | `cd frontend && npm run dev` |
| آزمون‌های سرور | `cd backend && ../.venv/bin/python -m pytest` |
| آزمون‌های سرور روی PostgreSQL (پیش از ادغام هر بسته، از 6.1) | `cd backend && NIKYAR_DB_ENGINE=postgres NIKYAR_DB_PASSWORD=... ../.venv/bin/python -m pytest` |
| بررسی و قالب‌بندی کد سرور | `cd backend && ../.venv/bin/ruff check . && ../.venv/bin/ruff format .` |
| آزمون واحد رابط کاربری | `cd frontend && npm test` |
| آزمون مرورگر (لپ‌تاپ، مانیتور بزرگ، موبایل) | `cd frontend && npm run e2e` |
| بررسی نوع‌ها و کیفیت کد | `cd frontend && npm run typecheck && npm run lint` |
| به‌روزرسانی نوع‌های API پس از تغییر سرور | `cd frontend && npm run api:types` |
