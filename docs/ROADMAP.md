# نقشه‌ی راه نیک‌یار (نسخه‌ی ۲)

> اصل راهنما: **اول هسته، بعد ماژول‌ها.** هر ماژول ERP (پرسنلی، انبار، حسابداری و…) فقط از
> امکانات هسته استفاده می‌کند و هیچ چیزی را از نو نمی‌سازد: فرم‌ساز، فرایندساز، فهرست‌های پایه،
> دسترسی‌ها، پیوست، شماره‌گذاری، سوابق تغییرات و اعلان‌ها.

هر فاز یک **خروجی قابل‌تحویل و قابل‌تست** دارد. فاز بعدی فقط وقتی شروع می‌شود که فاز قبلی
تأیید مالک محصول را گرفته باشد.

---

## فاز ۰: پایه‌ی فنی ✅
| مورد | توضیح |
|---|---|
| فرانت‌اند جدید | React + TypeScript + Tailwind v4 + کامپوننت‌های **وایب‌فارسی** |
| اتصال MCP وایب‌فارسی | در `.mcp.json` تا همه‌ی جلسه‌های بعدی خودکار وصل شوند |
| قوانین طراحی | `AGENTS.md`: راست‌چین، اعداد فارسی، تقویم شمسی، اعتبارسنجی ایرانی |
| ساختار ماژولار بک‌اند | `platform/` (هسته) جدا از `modules/` (ماژول‌های تجاری) |

## فاز ۱: هسته‌ی مرکزی (Platform Core) ✅
| زیرسیستم | قابلیت‌ها |
|---|---|
| **۱-۱ کاربران و احراز هویت** | ورود، خروج، تغییر رمز، قفل حساب پس از تلاش ناموفق، پروفایل |
| **۱-۲ ساختار سازمانی** | واحدهای درختی، سمت‌ها، متصدی، مدیر واحد، تاریخچه‌ی انتصاب |
| **۱-۳ نقش‌ها و دسترسی‌ها (RBAC)** | هر ماژول مجوزهای خودش را اعلام می‌کند (مثلاً `personnel.employee.edit`)؛ نقش = مجموعه‌ای از مجوزها |
| **۱-۴ مدیریت فهرست‌های پایه (Lookup Manager)** | دو نوع فهرست: **سیستمی** (قفل؛ منطق برنامه به آن وابسته است و کاربر نمی‌تواند کم یا زیادش کند) و **قابل‌ویرایش** (کاربر کامل مدیریت می‌کند). پشتیبانی از فهرست درختی، ترتیب، فعال/غیرفعال |
| **۱-۵ فرم‌ساز** | طراحی فرم با کشیدن و رها کردن، بخش‌ها و ستون‌ها، ۲۰+ نوع فیلد ایرانی (کد ملی، شبا، موبایل، تاریخ شمسی، مبلغ تومان، انتخاب از فهرست پایه…)، اعتبارسنجی، نمایش شرطی، نسخه‌بندی و انتشار |
| **۱-۶ فرایندساز (BPMN)** | طراحی فرایند؛ هر مرحله یک **فرم از کتابخانه‌ی فرم‌ها** می‌گیرد با سطح دسترسی هر فیلد (قابل‌ویرایش / فقط‌خواندنی / مخفی)؛ انتساب به سمت/واحد/نقش/مدیر؛ شرط مسیر از روی فیلدها؛ **اقدام سیستمی** (فراخوانی ماژول‌ها، مثلاً «ثبت در پرونده‌ی پرسنلی») |
| **۱-۷ کارتابل** | دریافت، انجام، ارجاع، یادداشت، پیگیری با نقشه‌ی فرایند |
| **۱-۸ سرویس‌های مشترک** | پیوست فایل، شماره‌گذاری خودکار (با ریست سالانه‌ی شمسی)، **سوابق تغییرات (Audit)** برای هر رکورد، اعلان درون‌برنامه‌ای |
| **۱-۹ تنظیمات و لایسنس** | تنظیمات سازمان، ماژول‌ها، لایسنس |

**معیار پایان فاز ۱:** مدیر سامانه بدون یک خط کد، یک فرم و یک فرایند «درخواست مرخصی» بسازد،
منتشر کند و کارمندها از کارتابل استفاده کنند.

## فاز ۲: ماژول پرونده‌ی پرسنلی جامع ✅
| بخش | محتوا |
|---|---|
| مشخصات هویتی | نام، نام خانوادگی، نام پدر، **کد ملی (با کنترل رقم)**، شماره و محل صدور شناسنامه، تاریخ تولد، جنسیت، وضعیت تأهل، وضعیت نظام وظیفه، دین، ملیت |
| اطلاعات تماس و نشانی | موبایل، تلفن، ایمیل، **استان و شهر**، کد پستی، نشانی کامل |
| اطلاعات استخدامی | کد پرسنلی (شماره‌گذاری خودکار)، نوع استخدام، تاریخ استخدام، واحد، سمت، وضعیت اشتغال |
| تحصیلات | مقطع، رشته، دانشگاه، معدل، سال فراغت (چندردیفی) |
| سوابق کاری | سازمان، سمت، از تاریخ تا تاریخ، علت ترک (چندردیفی) |
| افراد تحت تکفل | نام، نسبت، کد ملی، تاریخ تولد (چندردیفی) |
| حساب‌های بانکی | بانک، **شماره‌ی شبا (با کنترل)**، شماره‌ی کارت، حساب اصلی |
| بیمه | نوع بیمه، شماره‌ی بیمه، سابقه |
| مدارک | پیوست تصویر کارت ملی، شناسنامه، مدرک تحصیلی و… |
| **فیلدهای سفارشی (Low-code)** | سازمان بدون برنامه‌نویسی، فیلد یا بخش جدید با فرم‌ساز به پرونده اضافه می‌کند |
| گزارش و جستجو | جستجوی پیشرفته، فیلتر، خروجی اکسل |
| یکپارچگی با فرایند | مثلاً فرایند «استخدام» در پایان، پرونده را خودکار می‌سازد |

**فهرست‌های پایه‌ی این ماژول:**
- **سیستمی (قفل):** جنسیت، وضعیت تأهل، وضعیت نظام وظیفه، وضعیت اشتغال، نسبت خانوادگی؛ چون منطق برنامه روی آن‌هاست
- **قابل‌ویرایش:** نوع استخدام، مقطع تحصیلی، رشته، دانشگاه، بانک، نوع بیمه، نوع مدرک، دین
