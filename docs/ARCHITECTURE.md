# معماری

## نمای کلی

- **سرور**: Django 5.2 (LTS) + Django REST Framework؛ سند API خودکار با drf-spectacular در `/api/docs/`.
- **رابط کاربری**: React 19 + TypeScript + Vite + Tailwind CSS 4 + **shadcn/ui** (حالت راست‌به‌چپ، سبک فشرده‌ی Mira، پایه‌ی Radix).
- **اجرا**: در نصب سازمانی، `backend/serve.py` (Waitress) هم API و هم رابط ساخته‌شده (`frontend/dist`) را از یک درگاه روی همه‌ی کارت‌های شبکه سرو می‌کند؛ هر نشانی غیر از `/api/` به `index.html` برمی‌گردد.
- **داده‌ی هر نصب** در `backend/data/` (پایگاه SQLite، کلید امنیتی، فایل‌ها). PostgreSQL با متغیرهای `NIKYAR_DB_*` (راهنما در `backend/config/settings.py`).

### تنظیمات

```python
# apps.py
nikyar_settings = [SettingsSection(code="org-profile", title="مشخصات سازمان", serializer="core.org.sections.OrgProfileSettings")]
# هر فیلد سریالایزر برچسب فارسی و default دارد؛ اعتبارسنجی با validate_<field>.
# API: GET/PUT /api/settings/org-profile/ (مجوز settings.manage) — خواندن در کد: core.settings.service.read("org-profile")
```

بخشی که داده‌ی ساخت‌یافته‌ی خودش را دارد (مثل «شماره‌گذاری اسناد») `serializer` ندارد: در فهرست بخش‌ها می‌آید ولی API و فرمش را خودش می‌سازد.

فیلد فایل در تنظیمات و فرم‌ها `FileRefField` است (شناسه‌ی فایل): با ذخیره فایل جدید تصاحب و فایل قبلی حذف می‌شود؛ در سوابق نام فایل ثبت می‌شود.

در رابط کاربری، فرم هر بخش در `pages/admin/settings/` ساخته و در `SECTION_FORMS` صفحه‌ی تنظیمات ثبت می‌شود (قاب مشترک: `SettingsForm`). نام سازمان بدون ورود از `/api/org/branding/` خوانده می‌شود (`useBranding`).
- آزمون مرورگر اجراکننده‌ی کارها را هم اجرا می‌کند (هر ثانیه)؛ آزمون بازیابی پشتیبان در پروژه‌ی جدای `restore` پس از همه‌ی آزمون‌ها و به‌تنهایی اجرا می‌شود.
- آزمون‌های سرور روی پایگاه SQLite فایلی اجرا می‌شوند (نه حافظه)، مثل نصب واقعی؛ آزمون‌های هم‌زمانی واقعی‌اند.
- `HasPerm` لایسنس را هم اعمال می‌کند: نمای ماژولی که در لایسنس نیست ۴۰۳ با کد `module_disabled`، و پس از انقضا هر نوشتن ۴۰۳ با کد `license_expired` (مگر نماهای `license_exempt = True`: بارگذاری لایسنس، پشتیبان‌گیری، خوانده کردن اعلان، تنظیم دریافت اعلان).
- نوع‌های TypeScript رابط کاربری از سند OpenAPI سرور ساخته می‌شوند: `cd frontend && npm run api:types` (پس از هر تغییر API).

### جدول داده

```tsx
const view = useTableView("employees", { defaultSort: "name" })       // نشانی صفحه + ترجیحات کاربر
const table = useDataTable({ view, columns, data, getRowId })          // سمت مرورگر
// سمت سرور: useQuery({ queryKey: ["employees", view.query], ... }) و rowCount={data.count}
<DataTable table={table} view={view} caption="…" rowHref={(r) => `/…/${r.id}`} exportFileName="…" />
```

- جست‌وجو، مرتب‌سازی، فیلترها و صفحه در **نشانی صفحه** می‌مانند (اشتراک‌پذیر، دکمه‌ی بازگشت).
- ستون‌های نمایان، عرض، سنجاق و تراکم **ترجیح هر کاربر** در حافظه‌ی مرورگر.
- `meta` هر ستون: `label` (نام فارسی)، `primary` (پیوند ردیف و عنوان کارت موبایل)، `wrap` (ستون متنی که فضای اضافه را می‌گیرد و شکسته می‌شود)، `filterOptions` (فیلتر چندانتخابی)، `align`، `exportValue`.
- جدول در عرض صفحه جا می‌شود و نوار پیمایش داخلی ندارد: ستون‌های کوتاه به اندازه‌ی محتوا، ستون‌های `wrap` بقیه‌ی عرض. عرض ثابت فقط برای ستون سنجاق‌شده یا ستونی که کاربر عرضش را تغییر داده.
- روی موبایل هر ردیف یک کارت است.
- `compact` برای فهرست‌های کوتاه و ثابت: بدون نوار ابزار و صفحه‌بندی.

### سلسله‌مراتب متن و راهنما (قاعده‌ی مالک محصول)

- **متن اصلی** (برچسب، مقدار فیلد، دکمه، محتوای جدول): `text-xs` (۱۳px).
- **متن کمکی** (توضیح، راهنما، اطلاعات جانبی، حجم و زمان فایل): یک پله کوچک‌تر `text-2xs` (۱۲px) و کم‌رنگ؛ هرگز هم‌اندازه‌ی متن اصلی.
- **راهنمای توضیحی** به‌طور پیش‌فرض جمع‌شده است: نشانه‌ی ⓘ (`components/info-tip.tsx`) کنار برچسب یا عنوان؛ با نشانگر ماوس یا زدن (لمسی و صفحه‌کلید) باز می‌شود. صفحه‌خوان متن را با `aria-describedby` همراه همان فیلد یا بخش می‌شنود.
  - `FormField description`، `Section description` و `PageHeader description` همه ⓘ هستند.
- **فقط اطلاعاتی که همیشه باید دیده شود** باز نمایش داده می‌شود، با متن کوچک: مقدار پویا، شمارنده، نتیجه‌ی محاسبه، وضعیت رکورد.
  - `FormField hint`، `Section meta`، `PageHeader meta`.
- پیام خطا، متن پنجره‌ی تأیید و پیام حالت خالی متن اصلی‌اند، نه راهنما.

### فرم

`useAppForm(schema, defaults)` + `Section` + `FormGrid` (یک/دو/سه ستون بر اساس عرض واقعی بخش) + `FormField` (برچسب کنار فیلد با عرض ثابت ۸rem، بالای فیلد روی موبایل؛ راهنما در ⓘ با `description`، اطلاعات همیشه‌پیدا با `hint`) + `ErrorSummary`. مقدار فیلدهای ایرانی همیشه یکسان‌سازی‌شده (ارقام لاتین) است. تاریخ: `JalaliDateInput` (تایپ مستقیم با جداکننده‌ی خودکار یا انتخاب از تقویم آوان) با مقدار رشته‌ی شمسی `1405/08/14` و اعتبارسنجی `schemas.jalaliDate`.

## قواعد

- متن کمکی همیشه یک پله کوچک‌تر از متن اصلی است و راهنمای توضیحی در ⓘ جمع می‌شود (بخش «سلسله‌مراتب متن و راهنما»).
- همه‌ی متن‌های کاربر فارسی رسمی؛ ارقام نمایشی فارسی (`formatNumber`, `toFaDigits`)؛ تاریخ‌ها شمسی.
- فقط کلاس‌های منطقی Tailwind (`ms-`, `pe-`, `start-`, `text-start`).
- رنگ‌ها فقط از توکن‌های `index.css`؛ رنگ هرگز تنها حامل معنا نیست. نوار پیمایش همه‌جا باریک و هم‌رنگ پوسته است (`--scrollbar-thumb`)؛ نوار پیمایش پیش‌فرض مرورگر نمایش داده نمی‌شود.
- کد مرده، تکراری یا یتیم نگه داشته نمی‌شود؛ هر وابستگی باید استفاده شود.
