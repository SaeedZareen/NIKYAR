# معماری نیک‌یار

## نمای کلی

```
┌──────────────────────────────┐
│  فرانت‌اند (React + bpmn-js)  │  ← رابط فارسی، طراح فرایند، کارتابل
└──────────────┬───────────────┘
               │  REST API (/api/...)
┌──────────────▼───────────────┐
│  بک‌اند (Django + DRF)        │
│  ┌────────┐ ┌──────────────┐ │
│  │  core  │ │   workflow   │ │  ← ماژول‌ها (اپ‌های جنگو)
│  └────────┘ └──────┬───────┘ │
│                    │         │
│          ┌─────────▼───────┐ │
│          │ SpiffWorkflow   │ │  ← موتور اجرای BPMN
│          └─────────────────┘ │
└──────────────┬───────────────┘
               │
        ┌──────▼──────┐
        │ PostgreSQL  │
        └─────────────┘
```

**«مونولیت ماژولار»**: یک برنامه‌ی واحد که داخلش به ماژول‌های مستقل تقسیم شده است.
نصب و نگهداری‌اش برای مشتری ساده است و هر ماژول جداگانه قابل فروش است.

## ساختار پوشه‌ها

```
backend/
  config/                 تنظیمات و مسیرهای اصلی
  apps/
    core/                 هسته: کاربران، چارت سازمانی، سمت‌ها، لایسنس
      modules.py          رجیستری ماژول‌ها و بررسی لایسنس
      assignment.py       منطق «چه کسی کار را انجام دهد»
    workflow/             گردش کار
      engine.py           تنها نقطه‌ی ارتباط با موتور BPMN
      services.py         منطق کسب‌وکار (شروع، انجام، ارجاع، لغو)
      samples/            فرایندهای نمونه
frontend/
  src/
    pages/                صفحه‌ها
    components/           اجزای مشترک (فرم پویا، تقویم شمسی، نمایشگر دیاگرام)
    designer/             طراح فرایند: پنل فارسی، ترجمه، ابزارها
```

## افزودن یک ماژول جدید ERP (مثلاً انبار)

1. یک اپ جدید بسازید: `backend/apps/inventory/`
2. در `apps.py` آن، `nikyar_module` را تعریف کنید:
   ```python
   nikyar_module = {
       "code": "inventory", "title": "انبار و کالا",
       "is_core": False,              # ماژول پولی است و با لایسنس فعال می‌شود
       "depends": ["core", "workflow"],
   }
   ```
3. آن را به `NIKYAR_APPS` در `config/settings.py` اضافه کنید.
4. در ویوهای آن، `nikyar_module = "inventory"` و مجوز `ModuleEnabled` را بگذارید.
5. برای اتصال به گردش کار: در پایان یک فرایند (مثلاً «درخواست کالا») ماژول انبار
   سند خروج را می‌سازد. *(اتصال «تسک سرویس» به ماژول‌ها در نقشه‌ی راه است.)*

## تصمیم‌های کلیدی

| تصمیم | دلیل |
|---|---|
| موتور SpiffWorkflow (LGPL) | متن‌باز، پایتونی، بدون هزینه‌ی لایسنس تجاری (برخلاف Camunda 8) |
| فرمت BPMN با پسوند camunda | استاندارد صنعتی؛ فایل‌ها در ابزارهای دیگر هم باز می‌شوند |
| پنل خصوصیات اختصاصی فارسی | کاربر غیرفنی به‌جای کدنویسی، از فهرست انتخاب می‌کند |
| نسخه‌بندی فرایند | درخواست‌های در جریان با همان نسخه‌ای که شروع شده‌اند تمام می‌شوند |
| ذخیره‌ی وضعیت موتور در پایگاه داده | پس از ری‌استارت سرور، هیچ درخواستی گم نمی‌شود |
| قفل ردیف (`select_for_update`) | دو نفر نمی‌توانند هم‌زمان یک پرونده را تغییر دهند |
