# راهنمای لایسنس (برای مالک محصول)

هر نصب نیک‌یار پس از نصب **۳۰ روز آزمایشی** کار می‌کند (تا ۵۰ کاربر فعال، همه‌ی ماژول‌ها). پس از آن، بدون لایسنس معتبر سامانه **فقط‌خواندنی** می‌شود: هیچ اطلاعاتی پاک نمی‌شود، ولی ثبت و ویرایش ممکن نیست تا لایسنس بارگذاری شود.

لایسنس یک فایل کوچک (`.nikyar-license`) است که شما با **کلید خصوصی** خودتان امضا می‌کنید. هر تغییری در فایل (مثلاً افزایش تعداد کاربر) امضا را باطل می‌کند.

## ۱. ساخت کلید (فقط یک‌بار)

روی لپ‌تاپ خودتان، در پوشه‌ی نیک‌یار روی `license-tool.bat` **دوبار کلیک کنید** و گزینه‌ی `1` را بزنید (یا در خط فرمان: `license-tool.bat keygen`).

- یک «عبارت عبور» برای محافظت از کلید دو بار می‌پرسد (هنگام تایپ چیزی نمایش داده نمی‌شود؛ طبیعی است). اگر خالی بگذارید، تأیید می‌خواهد. عبارت عبور را فراموش نکنید؛ هر بار صدور لایسنس آن را می‌پرسد.
- اگر کلید از قبل ساخته شده باشد، ابزار آن را بازنویسی نمی‌کند. فقط تا وقتی هیچ لایسنسی صادر نکرده‌اید، با گزینه‌ی `4` کلید تازه بسازید.
- **کلید خصوصی** در `C:\Users\<نام شما>\NIKYAR-license-key\nikyar-license.private.pem` ذخیره می‌شود. از آن **یک نسخه روی فلش** نگه دارید. هر کس این فایل را داشته باشد می‌تواند لایسنس بسازد؛ آن را برای کسی نفرستید و در پوشه‌ی نیک‌یار یا گیت‌هاب نگذارید (ابزار هم اجازه نمی‌دهد).
- **کلید عمومی** در `backend\core\licensing\owner_public_key.pem` نوشته می‌شود. این فایل محرمانه نیست و باید در مخزن باشد تا همه‌ی نصب‌ها لایسنس‌های شما را بشناسند:

```
git add backend/core/licensing/owner_public_key.pem
git commit -m "Owner license public key"
git push
```

(یا متن همان فایل را برای جلسه‌ی توسعه بفرستید تا ثبت شود.)

> اگر کلید را دوباره بسازید (گزینه‌ی `4`)، همه‌ی لایسنس‌های صادرشده‌ی قبلی باطل می‌شوند و کلید عمومی تازه را هم باید دوباره در مخزن ثبت کنید.

## ۲. صدور لایسنس برای یک مشتری

1. مشتری در صفحه‌ی «مدیریت سامانه › ماژول‌ها و لایسنس» **شناسه‌ی نصب** (مثل `NK-1A2B3C4D-5E6F7A8B`) را کپی و برای شما می‌فرستد.
2. روی لپ‌تاپ خودتان روی `license-tool.bat` دوبار کلیک کنید و گزینه‌ی `2` را بزنید (یا `license-tool.bat issue`).

به ترتیب می‌پرسد: شناسه‌ی نصب، نام سازمان، سقف کاربران فعال، ماژول‌ها (`all` یعنی همه، `none` یعنی فقط هسته) و تاریخ اعتبار (`YYYY-MM-DD` میلادی). نمونه‌ی یک‌خطی:

```
license-tool.bat issue --install-id NK-1A2B3C4D-5E6F7A8B --org "شرکت نمونه" --users 50 --modules all --days 365
```

3. فایل `<شناسه>.nikyar-license` ساخته می‌شود؛ آن را برای مشتری بفرستید.
4. مشتری در همان صفحه «انتخاب فایل لایسنس» و «فعال‌سازی لایسنس» را می‌زند. بلافاصله فعال می‌شود.

بررسی یک فایل: گزینه‌ی `3` و کشیدن فایل لایسنس روی پنجره (یا `license-tool.bat show <فایل>`).

## نکته‌ها

- **تمدید:** لایسنس تازه با تاریخ جدید صادر کنید؛ بارگذاری آن جایگزین قبلی می‌شود. ۳۰ روز پیش از پایان اعتبار، نوار هشدار به راهبر سامانه نشان داده می‌شود.
- **سقف کاربران:** کاربر فعال تازه یا فعال‌کردن کاربر غیرفعال، پس از رسیدن به سقف، با پیام روشن رد می‌شود. غیرفعال‌کردن کاربران همیشه ممکن است.
- **سرور تازه:** شناسه‌ی نصب در پوشه‌ی `backend\data` است. اگر سازمان روی سرور تازه نصب کند و پشتیبان را بازیابی کند، شناسه‌ی نصب عوض شده است و لایسنس تازه برای شناسه‌ی جدید لازم است.
- **ماژول‌ها:** هسته (کاربران، ساختار سازمانی، اعلان‌ها، پشتیبان‌گیری و…) همیشه فعال است. ماژول‌های قابل فروش از نسخه‌های بعد اضافه می‌شوند و در لایسنس روشن یا خاموش می‌شوند.
